Repo context the ask lands on (verified 2026-08-17 at `7cdc812`; cites, not restatement):

- The Tuesday freeze is the payer incident recorded in `docs/handover/payer-status-page.md`
  (Tuesday 09:02–09:21, p95 `/intake` flat ~600ms all week with one ~20-min spike past
  30s) — the D4/RIV-141 path ADR 0010 bounded. Bounded is not alerted: nothing in the
  estate would have paged anyone (the client is right — no dashboard, SLO, or alerting
  config exists in the tree; nearest prior art is ADR 0006's metadata-only tracing).
- The raw latency-log corpus the ask references was not handed over into the repo
  (searched `docs/handover/`, `docs/research/`, `logs/` 2026-08-17); the status-page
  snapshot above is the only in-tree incident evidence. See Open.
- **No AI patient-summary endpoint exists on `main`.** `services/ai-assistant/app.py`
  serves `/healthz` (:213), `/intake-instructions` (:218), `/visit-chat` (:820) only;
  both AI features are safe by construction (closed vocabulary, no chart free text to
  the vendor) precisely because of D13 (no BAA — `docs/debt-log.md`). A summary that
  grounds against the chart is, by nature, the first feature to carry record-derived
  text on the vendor-egress path. See Open, and the ⚠ flags below.
- Critical span today: `services/gateway/app.py:251` (`POST /intake`, `_post_checked`)
  → `services/intake-service/app.py:280` (`create_intake`) → `:343`
  (`_verify_eligibility_guarded`) → `:809-813` (httpx GET to eligibility-service).
- Any structured record this item emits is a log surface: `docs/phi-logging-policy.md`
  rules 2/3 bind (internal `patient_id` permitted; name/DOB/member_id/etc. never), and
  `docs/landmines.md` §3 requires adversarial negative tests. Known-open leaks on
  these very surfaces (TODO-46/47, D1b, policy register) are owned there — this item
  must not widen them and does not silently fix them.

| ID | Requirement | Notes |
|----|-------------|-------|
| w7-REQ-1 | When a request traverses the intake critical path (portal → gateway → intake-service → eligibility-service), an operator can reconstruct that single request end-to-end from emitted records alone — one correlation identifier follows it across every hop. | Today impossible: plain-text logs, no shared id |
| w7-REQ-2 | Records emitted for w7-REQ-1 carry no PHI: `docs/phi-logging-policy.md` rule 2 (only internal surrogate ids) and rule 3 (no exception strings) hold on every new field, proven by adversarial negative tests. | ⚠ human-gate adjacency: log surface; `docs/landmines.md` §3 |
| w7-REQ-3 | Instrumentation changes nothing the front desk or patient can observe: no added blocking on the request path, and a fault in tracing/metrics never fails or slows a registration. | ADR 0010 bounds are pinned — instrumentation must not perturb them |
| w7-REQ-4 | An SLO for the intake path exists in the tree, stated as latency and error-rate targets over a defined window, grounded in the measured baseline (w7-D-1). | Target numbers proposed at spec stage from baseline; owner approves at freeze |
| w7-REQ-5 | A golden-signals dashboard spec for the intake path exists (latency, traffic, errors, saturation), each signal traceable to a real emitting site in the code. | Spec document, not a built dashboard — see out-of-scope |
| w7-REQ-6 | When the intake-path SLO is breached, one alert fires and reaches a named destination without a human polling anything; demonstrated by replaying a Tuesday-class incident shape (payer degradation driving p95 past threshold for the alert window) and observing the alert. | Closes "20-min outage, zero alerts"; delivery channel is an owner call — see Open |
| w7-REQ-7 | Every clinical statement in an AI patient summary shown to a clinician is supported by that patient's stored record; a statement the record does not support is blocked before a clinician can see it. | ⚠ human-gate: sits on the only vendor-egress path (D13); target endpoint does not exist on `main` — see Open |
| w7-REQ-8 | When the record lacks the information a summary would need, the output states that it is unknown or refuses — it never fabricates ("refuse if unknown"). | |
| w7-REQ-9 | If the guardrail cannot run (fault, config gap), the summary is withheld — fail closed; an unchecked summary never reaches a clinician. | The `/ai` fail-closed guards are the estate's stated quality bar (CLAUDE.md §4) |
| w7-REQ-10 | The guardrail is demonstrated adversarially: a test suite that actively attempts to make the summary state facts the seed corpus does not support, with every attempt blocked — the evidence is the failing-attack suite, not the absence of complaints. | The client's explicit bar ("shown it can't"); `docs/landmines.md` §3 |
